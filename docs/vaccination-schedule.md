# 儿童免疫程序表（电子化版本）

这份资料根据用户提供的纸质《儿童免疫程序表》照片逐行录入，作为项目后续“疫苗计划”功能的初始资料。用户确认这份资料来自浙江省；照片没有标注发布机构、发布日期和价格有效期，因此价格只代表照片上的记录，不代表当前收费标准。

应用页面将原表的①、②等剂次符号显示为“💉 第一针”“💉 第二针”；连续的①②显示为“💉 第一针、第二针”。电子化原文保留照片写法，便于核对。

完整结构化数据见 [`vaccination-schedule.json`](./vaccination-schedule.json)。

国家层面的校验资料：

- [国家免疫规划疫苗儿童免疫程序及说明（2026年版）](https://www.ndcpa.gov.cn/jbkzzx/c100014/common/content/content_2073005020766703616.html)
- [非免疫规划疫苗使用指导原则（2020年版）](https://www.chinacdc.cn/jkyj/mygh02/jswj2026/202606/t20260624_1837332.html)

## 使用边界

- 免费/自费、可替代关系、适用年龄和剂次以国家及本地最新免疫程序、疫苗说明书和接种门诊现场核对结果为准。
- 带“※”的免费项目，照片注释写明可以由非免疫规划疫苗替代；联合疫苗和单苗不能叠加计算。
- 表中“13价肺炎TT”“13价肺炎197”等写法保留原表简称，开发时应增加“门诊原表名称”和“标准疫苗名称”两个字段，避免把简称当成全国统一产品名称。
- 价格包含接种费的表述来自照片，价格会随地区、产品、政策和门诊库存变化。

## 后续开发计划

### 第一阶段：资料和数据模型

1. 将年龄节点、免费项目、自费项目、剂次、替代关系、价格、地区、来源和有效期拆成结构化字段。
2. 保留“照片原文”和“标准名称”两套名称；不能确认的简称不自动改写。
3. 增加资料版本和更新时间，价格默认标为“仅供参考”，不参与医学判断。

### 第二阶段：宝宝疫苗档案

1. 在“配置中心”增加“疫苗计划”，使用宝宝生日自动显示当前年龄段。
2. 按“免费疫苗”“自费疫苗”分组，并提供“建议时间、已接种、跳过、待核对”状态。
3. 每条计划显示完整日期、年龄节点、剂次、名称和来源；超过当前年龄的计划按日期排列，不一次塞满首页。
4. 支持手动调整本地门诊版本，避免把照片中的单一价格当成全国价格。

### 第三阶段：提醒和记录

1. 首页任务提醒增加“下一次疫苗参考”，与喂奶、用药保持同一任务卡样式。
2. 记录接种日期、疫苗名称、剂次、接种门诊、批号（可选）和备注；不保存不必要的个人信息。
3. 已记录的剂次自动从待执行列表中移除，并保留编辑入口。
4. 逾期只提示“请和接种门诊核对补种安排”，不自行生成补种医学方案。

### 第四阶段：验证和发布

1. 用未满月、满月、6月龄、18月龄和6周岁等生日样例测试年龄计算和跨月提醒。
2. 检查联合疫苗替代后不会重复提示对应的单苗。
3. 在手机视图验证大字、清晰按钮、横向表格和弹窗文字不遮挡。
4. 在 README 和更新日志列出官方资料与本地照片资料，明确价格和接种安排需要现场核对。

## 待确认项

- 这张表对应的城市、门诊名称、发布日期和适用版本。
- “13价肺炎TT”“13价肺炎197”的正式产品名称及对应说明书。
- 价格是否仍有效，以及“AC结合”“ACYW135结合”“白破”等项目具体对应的产品。
- 当前门诊是否已经按最新国家免疫程序执行，尤其是免费项目和替代关系。
